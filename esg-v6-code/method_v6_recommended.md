# 推荐方法（回到起点，定稿建议）

- 日期：2026-11-08
- 主题（不变）：ESG 年报图片与本地上下文不匹配
- 最终目标（不变）：按不匹配的类型聚类，先记录现象、后聚类、再按大类命名
- 约束（不变）：只比本地上下文；最终审核十万多份年报，生产零人工；比较不用大模型当裁判

## 一句话

**结构化字段逐项比对，找出不匹配、记录现象特征；不预先判类型，用无监督聚类把不匹配聚成大类，聚完再命名。**

## 1. 流程（四步）

```
解析 → 分流 → 逐项比对（规则）→ 记录现象特征 → 聚类 → 事后命名 → 汇总
```

### 第一步：解析，本地池冻结

- MinerU 解析，本地上下文就用 `context_dynamic_v35` 的池，冻结成代码。
- 本地为空的单独记一类，不丢掉；图注单独存，不算叙述支撑。

### 第二步：分流

- 图表 / 证书 / 照片 / 复合图，先分开。
- 复合图先拆，拆不开就排除，排除比例单独报。
- 分流本身全自动，准确率在标定集上单独报。

### 第三步：逐项比对（规则，不用大模型判）

- 图和本地文字都先转成结构化字段：主体、属性、值、时间、地点、人物/机构、单位、限定词。图这边用 VLM 只做提取，本地这边用规则提取；**提取可以用模型，比较不能用模型判**。
- 逐项比，只比图和本地这两边：
  - 证书 / 图表：奖项 / 指标、发证单位 / 主体、日期 / 年份、数值，归一化后逐字、逐数对。对上就是支持，对不上就是字段差异，没出现就是无支撑。
  - 照片：只比到主题级。图里的关键实体、活动主题词在本地出现没有；再加 CLIP 本地 top 分做一个特征，不当最终判定。
  - 限定词：本地有限定（全公司 / 某工厂、全年 / 试点、已实现 / 目标），图上丢了没有，按词表判。
- 这一步只产出两样东西：
  1. **是否不匹配**：任一字段对不上，或无支撑，或主题对不上，就是不匹配；全对上就是一致。
  2. **现象特征**：下面第 4 步的向量，不含类型判断。

### 第四步：聚类（无监督），聚完再命名

- 只聚不匹配的，一致的不进聚类。
- 特征（每张不匹配的图一条）：
  - 图类型（证书 / 图表 / 照片）
  - 本地段数、本地字数
  - 实体重合数、奖项命中、日期命中、指标命中、数值命中（各 0/1）
  - 字段差异方向：值大了 / 小了、时间早了 / 晚了、主体换了、限定丢了（有就记，没有记 0，不判类型）
  - CLIP 本地 top 分、本地 top 与对照 top 的差（照片）
  - 图里有没有数字、日期
- 方法：KMeans 为主，层次聚类做对照；k 值用轮廓系数选，不先定死；做稳定性检验（换个子样本、换个随机种子，簇还稳不稳）。
- 命名在后：看每个簇的中心长什么样，再给大类起名字。试点演示里，16 张证书自己聚成了一簇，G0021、G0040 两张照片聚成了一簇——名字是聚完才起的，不是先写好的。

## 2. 汇总

- 每家公司每年算一次：不匹配率、各簇占比，分类型、分 E/S/G 支柱、分年份。
- 主结果只报聚类稳定、特征清晰的大类；不稳定的小簇单独报，不硬并进大类。
- 报告里写清楚：分流准确率、聚类稳定性、排除比例（复合图、无本地上下文各占多少）。

## 3. 人在哪里

- 生产（十万份）：零人工。
- 开发（一次）：小样本标定，500–1,000 张，人工标一次，用来报分流准确率、比对准确率、聚类稳定性，冻住阈值和词表。之后不再改。

## 4. 扔掉什么、留住什么

扔掉：
- 全文检索找锚点（本地口径已定，全文只做对照）
- TF-IDF / BM25 / LSA / CLIP 当最终锚定判定（CLIP 只留作一个特征）
- 一开始就判类型（预设标签）
- 人工逐张裁决（生产）
- 单一相似度分数当最终结论

留住：
- 先比本地、再比字段、后查限定，这个骨架
- 结构化字段两边对照
- 规则比对，不用大模型当裁判
- 照片主题级、证书图表字段级，这个粒度
- 聚类后命名，这个最终目标

## 5. 试点证据（为什么选这条路）

- 证书规则比对跑通了：G0004 16 张，奖项、日期命中全是 0，是硬结果。
- 实体重合是照片最稳的信号：G0066-2 靠“集体宣誓”原文命中，G0040 靠实体命中为 0。
- CLIP base 分不出细粒度（本地 top 全输给对照），所以 CLIP 只能当特征，不能当判定。
- 聚类演示跑通了：19 个不匹配实例，KMeans k=3，证书一簇、照片两簇，名字是聚完才起的。试点里没有值错、时间错的例子，所以那些细簇聚不出来，要等大样本。

## 6. 图文匹配程度怎么量（2026-11-08 晚补）

匹配程度不是一个总分，是一组分字段的率，聚类用的就是这组率。

每张图，对本地池算：

1. **主体匹配率** = 图里 distinctive 实体在本地出现的个数 / 图里 distinctive 实体总数。distinctive 指去掉“国际医学、医院、公司”这类通用词，剩下的才算。通用词出现不算分。
2. **项目 / 奖项匹配率** = 图里 distinctive 项目 / 奖项词在本地出现的个数 / 总数。证书的奖项名、图表的指标名，都走这一项。
3. **时间匹配率** = 图里日期在本地对上的个数 / 图里日期总数。只算年不算对上，要年+月（或完整日期）才算；只有年份的记 0，不记分。
4. **数值匹配率** = 图里数值在本地对上的个数 / 图里数值总数。只用于图表 / 证书上有数值的图；照片没有数值，记 NA，不算进平均。
5. **主题相似度** = CLIP 本地 top 分（照片专用），只当一个特征，不当最终判定。CLIP 分高不能证明一致，分低可以 flag。
6. **限定保留率** = 本地限定词在图上保留的个数 / 本地限定词总数。本地没有限定词，记 NA。

**不要把上面 6 项平均成一个总分。** 试点里单看总分会错：G0021 只靠 2023、2024 两个年份就拿到 0.67，看着高，其实照片和本地不匹配；G0066-1 听讲那张按整词算只有 0.0，看着低，其实主题是对的（核心词“培训”在本地）。所以匹配程度要以这组率的形式进聚类，让聚类自己去分，不要先合成一个数。

**是否不匹配的判定**，不靠总分过线，靠规则：
- 任一硬字段（主体 / 项目 / 日期 / 数值）对上了号但值不一样 → 不匹配（字段差异）
- 硬字段一个都没出现 → 不匹配（无支撑）
- 照片主题词一个都没出现，且 CLIP 分明显低 → 不匹配（主题不匹配）
- 全对上 → 一致

试点匹配度表：`pilot_match_degree.csv`（按整词算的覆盖率，有上面说的两个坑，正式版要用 distinctive + 核心词 + 年月全对的算法重算，见脚本注释）。

## 7. 图注也属于上下文（2026-11-08 晚纠正）

- 图注属于上下文，但支撑要分来源记：**叙述支撑**才算一致，**仅图注支撑**是弱支撑，记为不匹配现象，进聚类。
- 原因：图注是图自己带的说明，奖项名只出现在图注里，等于自己给自己作证，不是正文叙述的独立支撑。
- 试点重算（v6b，`pilot_v6b.py`）：23 张里一致 4 张、不匹配 19 张的总数不变，但 19 张里 15 张是仅图注支撑的证书、4 张完全无支撑（G0001、G0021、G0040，另有 1 张证书连图注都没有）；聚类 k=3，轮廓系数 0.885：簇 0 是 2 张完全无支撑（G0001 航拍 + 1 张无图注证书），簇 1 是 15 张仅图注支撑的证书，簇 2 是 G0021、G0040（本地有文字、图注均无命中）。

## 9. 匹配前的分类怎么做（2026-11-08 晚补）

- 先分四类：照片 / 证书·牌匾 / 图表 / 复合图，分错了后面就全错（照片走证书路线，字段命中全是 0，会被误判成不匹配）。
- 信号按优先级排，不用单一信号：
  1. MinerU 的类型：content_list 里已经标了 chart（本报告 17 个），直接当图表。
  2. 图注关键词：证书 / 奖 / 牌匾 / 联盟成员单位 / 成果 → 证书；对比图 / 消耗 / 占比 → 图表。
  3. VLM 的 Image Type 归一化映射（证书、证书扫描件、牌匾 → 证书；*照片、合影、建筑外景、实景 → 照片；拼接图 → 复合图）。但这个字段 42% 是空的（75/178），不能只靠它。
  4. CLIP 零样本分类：试点 23 张准确率 18/23，证书 16/16 全对，照片只对 2/7（3 张照片被误判成证书，G0040 被误判成复合图，G0021 复合图被误判成证书），相似度都挤在 0.30–0.35。CLIP 只能当证书检测器，不能当通用分类器。
  5. 复合图单独检：图内 OCR 出现图表词（对比图、电量、水量、占比、%）且同时有照片内容 → 复合图（例 G0021）。
- 决策：上面几条投票，MinerU 图表优先，证书关键词次之，复合图检查再次之，其余默认照片；信号打架的记不确定，进标定集人工判（只在开发阶段）。
- 验证：在标定集上报准确率和混淆矩阵，重点看照片误判成证书（试点 CLIP 是 3/7）；分类准确率要和匹配结果一起报，因为分类错会直接变成匹配错。
